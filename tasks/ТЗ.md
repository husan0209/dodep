## ЭТАП 1: Инфраструктура и DevOps Foundation

**Длительность:** 3-4 недели
**Команда:** 2 DevOps/SRE + 1 Security Engineer
**Приоритет:** 🔴 КРИТИЧЕСКИЙ (блокирует всё)

### 1.1 Цели этапа

```
Создать полностью автоматизированную инфраструктуру,
на которой будут работать все последующие сервисы.
Принцип: ни одного ручного действия в продакшене.
```

### 1.2 Задачи

```yaml
1.1_terraform_foundation:
  описание: "Базовая инфраструктура как код"
  задачи:
    - Структура Terraform-репозитория (modules, environments)
    - Terragrunt wrapper для DRY конфигов
    - AWS/GCP аккаунт: VPC, subnets (public/private), NAT Gateway
    - IAM роли и политики (least privilege)
    - S3 bucket для Terraform state + DynamoDB lock table
    - KMS ключи для шифрования
  артефакты:
    - terraform-infra/ репозиторий
    - README с архитектурной диаграммой сети
    - Документация по запуску
  критерии_приёмки:
    - terraform plan выполняется без ошибок
    - terraform apply создаёт инфру за < 15 минут
    - terraform destroy чисто удаляет всё
    
1.2_kubernetes_cluster:
  описание: "Kubernetes кластер production-ready"
  задачи:
    - EKS/GKE кластер (3 availability zones)
    - Node pools: system, application, data, spot
    - Cluster Autoscaler + Karpenter (AWS) настройка
    - Network Policies (Calico)
    - Pod Security Standards (restricted)
    - StorageClasses (gp3/pd-ssd)
    - Namespaces: platform, data, monitoring, security, staging
  конфигурация:
    environments:
      dev:
        nodes: 3-5 (spot instances)
        instance_type: t3.large / e2-standard-4
      staging:
        nodes: 5-8 (mixed spot + on-demand)
        instance_type: t3.xlarge / e2-standard-8
      production:
        nodes: 10-15 (on-demand, multi-AZ)
        instance_type: m6i.2xlarge / n2-standard-8
        autoscaling: 10-40 nodes
  критерии_приёмки:
    - kubectl get nodes показывает все ноды Ready
    - Autoscaling: 10→20 nodes за < 5 минут
    - Pod-to-pod коммуникация работает cross-AZ

1.3_service_mesh:
  описание: "Istio service mesh для безопасности и observability"
  задачи:
    - Istio установка (istioctl, ambient mode рассмотреть)
    - mTLS STRICT между всеми сервисами
    - Authorization Policies (deny-all по умолчанию)
    - Traffic management: timeout, retry, circuit breaker defaults
    - Istio Ingress Gateway (вместо отдельного ingress)
    - Rate limiting на mesh уровне
  конфигурация_istio:
    global:
      mtls: STRICT
      access_logging: true
      tracing_sampling: 100%  # dev/staging
    defaults:
      timeout: 30s
      retries: 3
      circuit_breaker:
        consecutive_errors: 5
        interval: 30s
        base_ejection_time: 30s
  критерии_приёмки:
    - Весь трафик между подами шифрован (проверить tcpdump)
    - Kiali dashboard показывает service graph
    - Circuit breaker срабатывает при 5 ошибках подряд

1.4_cicd_pipeline:
  описание: "CI/CD пайплайн для всех сервисов"
  задачи:
    - GitHub Actions: шаблоны для Rust, Go, Python, Frontend
    - Multi-stage Dockerfile для каждого языка
    - Distroless base images
    - Container Registry (ECR/Artifact Registry)
    - ArgoCD для GitOps деплоев
    - Argo Rollouts для canary deployments
    - Branch protection rules
    - Semantic versioning автоматизация
  pipeline_stages:
    ci:
      - lint (clippy/golangci-lint/ruff/eslint)
      - unit tests
      - integration tests (testcontainers)
      - security scan (Trivy + Semgrep)
      - build Docker image
      - push to registry
    cd:
      - ArgoCD auto-sync (dev)
      - ArgoCD manual sync (staging)
      - Argo Rollouts canary (production)
      - smoke tests post-deploy
      - auto-rollback on failure
  критерии_приёмки:
    - Push to main → auto deploy to dev за < 10 мин
    - Canary rollout: 5% → 25% → 50% → 100% (автоматически)
    - Rollback при > 1% error rate за < 2 мин

1.5_secrets_management:
  описание: "HashiCorp Vault для управления секретами"
  задачи:
    - Vault кластер (HA mode, 3 nodes)
    - Auto-unseal (AWS KMS / GCP KMS)
    - Kubernetes auth method
    - Secret engines: KV v2, Transit, PKI, Database
    - Vault Agent Injector для K8s pods
    - Rotation policies для DB credentials
    - Audit logging
  политики:
    - Каждый сервис имеет отдельную policy
    - TTL на dynamic secrets: 1 hour
    - Max versions: 10 (для rollback)
  критерии_приёмки:
    - Pods получают секреты через Vault Agent (не env vars)
    - DB credentials ротируются автоматически каждый час
    - Vault audit log → ClickHouse pipeline

1.6_cloudflare_setup:
  описание: "CloudFlare как edge-layer"
  задачи:
    - DNS настройка (проксированные записи)
    - SSL/TLS: Full (Strict) mode
    - WAF rules: OWASP top-10, custom gambling rules
    - Rate Limiting rules (по endpoint)
    - Bot Management
    - Page Rules / Cache Rules
    - CloudFlare Workers (geo-redirect, A/B testing)
    - Argo Smart Routing (оптимизация маршрутов)
  waf_rules:
    - SQL injection protection: ON
    - XSS protection: ON
    - Rate limit login: 10 req/min per IP
    - Rate limit API: 100 req/min per user
    - Block countries: по списку юрисдикций
    - Challenge suspicious: score > 30
  критерии_приёмки:
    - TTFB < 100ms из любой точки мира
    - WAF блокирует OWASP top-10 атаки
    - DDoS mitigation: выдерживает 1M rps L7
```

## ЭТАП 3: Слой данных — базы данных

**Длительность:** 3-4 недели
**Команда:** 2 Backend + 1 DBA + 1 DevOps
**Приоритет:** 🔴 КРИТИЧЕСКИЙ
**Зависимости:** Этап 1

### 3.1 Задачи

```yaml
3.1_postgresql_citus:
  описание: "PostgreSQL 16 + Citus — основная OLTP БД"
  задачи:
    - Citus кластер: 1 coordinator + 3 workers
    - Streaming replication (sync) для coordinator
    - Connection pooling: PgBouncer (transaction mode)
    - pg_partman для time-based partitioning (bets, transactions)
    - Начальная схема базы:
        - users (distributed by user_id)
        - wallets (distributed by user_id)
        - transactions (distributed by user_id, partitioned by month)
        - bets (distributed by user_id, partitioned by day)
        - kyc_records (distributed by user_id)
        - game_configs (reference table — реплицировано на все ноды)
        - currencies (reference table)
        - countries (reference table)
    - Row Level Security (RLS) policies
    - Audit trigger (все изменения → audit table)
    - Backup: WAL-G → S3 (continuous + daily full)
    - Point-in-time recovery тестирование
    - pg_stat_statements для мониторинга запросов
  schema_core:
    users:
      columns:
        - id: BIGSERIAL PRIMARY KEY
        - uuid: UUID UNIQUE NOT NULL DEFAULT gen_random_uuid()
        - email: VARCHAR(255) UNIQUE NOT NULL
        - phone: VARCHAR(20) UNIQUE
        - password_hash: VARCHAR(255) NOT NULL  # Argon2id
        - status: user_status_enum NOT NULL DEFAULT 'pending'
        - kyc_level: SMALLINT NOT NULL DEFAULT 0
        - country_code: CHAR(2) NOT NULL
        - currency_code: CHAR(3) NOT NULL
        - created_at: TIMESTAMPTZ NOT NULL DEFAULT NOW()
        - updated_at: TIMESTAMPTZ NOT NULL DEFAULT NOW()
        - last_login_at: TIMESTAMPTZ
        - metadata: JSONB DEFAULT '{}'
      indexes:
        - idx_users_email (email)
        - idx_users_phone (phone)
        - idx_users_uuid (uuid)
        - idx_users_country (country_code)
        - idx_users_status (status)
      distribution: HASH(id)
      
    wallets:
      columns:
        - id: BIGSERIAL PRIMARY KEY
        - user_id: BIGINT NOT NULL REFERENCES users(id)
        - currency_code: CHAR(3) NOT NULL
        - balance: NUMERIC(18,8) NOT NULL DEFAULT 0
        - locked_balance: NUMERIC(18,8) NOT NULL DEFAULT 0  # в ставках
        - version: INTEGER NOT NULL DEFAULT 0  # optimistic locking
        - created_at: TIMESTAMPTZ NOT NULL DEFAULT NOW()
        - updated_at: TIMESTAMPTZ NOT NULL DEFAULT NOW()
      constraints:
        - UNIQUE(user_id, currency_code)
        - CHECK(balance >= 0)
        - CHECK(locked_balance >= 0)
        - CHECK(balance >= locked_balance)
      distribution: HASH(user_id)  # co-located с users
      
    transactions:
      columns:
        - id: BIGSERIAL
        - user_id: BIGINT NOT NULL
        - wallet_id: BIGINT NOT NULL
        - type: tx_type_enum NOT NULL
          # deposit, withdrawal, bet_place, bet_win, bet_refund,
          # bonus_credit, bonus_wager, adjustment
        - amount: NUMERIC(18,8) NOT NULL
        - balance_before: NUMERIC(18,8) NOT NULL
        - balance_after: NUMERIC(18,8) NOT NULL
        - reference_type: VARCHAR(50)  # 'bet', 'payment', 'bonus'
        - reference_id: BIGINT
        - idempotency_key: UUID UNIQUE NOT NULL
        - status: tx_status_enum NOT NULL DEFAULT 'completed'
        - metadata: JSONB DEFAULT '{}'
        - created_at: TIMESTAMPTZ NOT NULL DEFAULT NOW()
      distribution: HASH(user_id)
      partition: RANGE(created_at) MONTHLY
      
    bets:
      columns:
        - id: BIGSERIAL
        - user_id: BIGINT NOT NULL
        - bet_type: bet_type_enum NOT NULL  
          # single, accumulator, system
        - status: bet_status_enum NOT NULL DEFAULT 'pending'
          # pending, active, won, lost, void, cashout
        - stake: NUMERIC(18,8) NOT NULL
        - potential_win: NUMERIC(18,8) NOT NULL
        - actual_win: NUMERIC(18,8) DEFAULT 0
        - odds: NUMERIC(12,6) NOT NULL
        - currency_code: CHAR(3) NOT NULL
        - sport_id: INTEGER
        - event_id: BIGINT
        - market_id: BIGINT
        - selection_id: BIGINT
        - placed_at: TIMESTAMPTZ NOT NULL DEFAULT NOW()
        - settled_at: TIMESTAMPTZ
        - ip_address: INET
        - device_fingerprint: VARCHAR(64)
        - metadata: JSONB DEFAULT '{}'
      distribution: HASH(user_id)
      partition: RANGE(placed_at) DAILY
      
  connection_pool:
    pgbouncer:
      pool_mode: transaction
      max_client_conn: 10000
      default_pool_size: 50
      reserve_pool_size: 10
      server_idle_timeout: 300
      
  backup:
    wal_g:
      schedule: "continuous WAL + daily full"
      retention: "30 daily + 12 monthly + 1 yearly"
      storage: S3 (cross-region)
      encryption: AES-256
      test_restore: weekly (automated)
      
  критерии_приёмки:
    - Citus кластер работает, таблицы distributed
    - PgBouncer держит 10K connections
    - PITR восстановление работает за < 30 мин
    - RLS политики предотвращают cross-user access
    - Audit triggers записывают все изменения

3.2_dragonflydb:
  описание: "DragonflyDB — кэш и сессии"
  задачи:
    - Кластер: 3 ноды (master + 2 replica)
    - Maxmemory: 64GB per node
    - Persistence: snapshot каждые 5 мин
    - Namespace-based isolation:
        - ns:sessions     — JWT refresh tokens, user sessions
        - ns:cache        — odds cache, user profile cache
        - ns:rate_limit   — rate limiting counters
        - ns:leaderboard  — sorted sets для рейтингов
        - ns:idempotency  — idempotency keys (TTL 24h)
        - ns:locks        — distributed locks
        - ns:features     — feature flags
    - Client libraries для Rust (fred) и Go (go-redis)
    - Мониторинг: metrics → VictoriaMetrics
  структура_ключей:
    sessions:
      pattern: "session:{user_id}"
      ttl: 7 дней
      value: JSON {token, device, ip, created_at}
    cache:
      pattern: "odds:{event_id}:{market_id}"
      ttl: 5-30 секунд (динамически)
      value: Protobuf serialized
    rate_limit:
      pattern: "rl:{type}:{identifier}:{window}"
      ttl: window duration
      value: counter
    leaderboard:
      pattern: "lb:{type}:{period}"
      type: sorted set
```
