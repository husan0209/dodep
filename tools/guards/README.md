# Architecture Guards

Инварианты микросервисной платформы, которые проверяются и в CI, и локально.

| Правило | Инвариант | Область |
|---------|-----------|---------|
| G1 | Деньги — только `Decimal` / целые (cents), не `f32/f64/float32/float64` | `services/rust/wallet-core/src`, `services/go/payment` |
| G2 | Сервисный Go-код логирует через `zap`/`slog`, не `fmt.Println` | `services/go/**` минус `_test.go` и `cmd/` |
| G3 | Приватные ключи не коммитятся (Vault / env) | `apps`, `services`, `libs`, `infra`, `docs`, `tools`, `gen` |
| G4 | Нет `@ts-ignore` / `@ts-nocheck` / `eslint-disable` | `apps`, `libs` |

## Локальный запуск

```bash
py tools/guards/architecture_guards.py            # все правила
py tools/guards/architecture_guards.py --rule G4  # одно правило
```

Код возврата ненулевой при нарушении — тот же контракт, что в CI.

## Почему исключения

- **G2 / `cmd/`** — CLI-точки входа (`migrate`, `seed`, `genhash`): stdout для
  них и есть интерфейс, они выполняются один раз и завершаются. Сервисный
  код (`main.go`, `internal/**`) логирует структурированно.
- **G2 / `_test.go`** — вывод тестов ожидаем.
- **G3 / dot-директории** — `.claude/`, `.qwen/` и подобные содержат
  забандленные документации agent-skills с обрезанными примерами ключей
  (Kubernetes-конфиги). Это вендоренный контент, не секреты проекта.
  CI использует `git grep` по явным путям вместо `grep -r .`.
- **G3 / сам guard** — файл проверки содержит строки-маркеры по определению.
- **G4** — директива на невключённое правило тоже нарушение: она молча
  гниёт и снимает проверку, когда правило однажды включат.

## Синхронизация с CI

Правила продублированы в `.github/workflows/architecture-guards.yml`.
Правки вносить в оба места. Перед коммитом полезно прогнать локальный
скрипт — он быстрее и даёт тот же список нарушений.
